01 · The bet

No pain today. Maximum leverage for tomorrow.

A 15-year-old isn't job-hunting — so we don't sell them a job skill. We sell a game they win daily, and the by-product is that data stops being scary. They're the cheapest users to reach (school, parents, peers), the stickiest to form a habit in, and the highest lifetime value once they grow into it.

Who + why them

The learner

Students in class 9–12 (14–18). Curious, phone-native, competitive, allergic to boredom. School teaches about computers but never lets them command data. They have time and neuroplasticity — the two things adult learners lack.

habit-formingpeer-drivenreward-motivatedshort attention
The shift we sell
“Databases are boring adult stuff I'll never use.”
↓
“I can ask any dataset a question and get the answer myself.”
Core problem

Data literacy is the single most transferable tech skill — and the one thing no school and no coding-toy teaches. Existing SQL tools are dry docs for adults with a deadline. Nothing is built for a bored teenager with 4 spare minutes.

Why SQL is perfect to gamify

Every query has one verifiable answer you can check in milliseconds. Query = asking a question. That's the exact prompt→attempt→instant-feedback loop Duolingo is built on — SQL fits it better than languages do.

Why now / why AI

AI can be an infinitely patient tutor, an infinite puzzle generator, and the bridge from plain English → SQL. We don't bolt AI on — it's how we personalise, explain, and let kids build something real.

02 · The core loop

One loop, run daily, on a real database.

Everything else is scaffolding around this 4-minute cycle. Queries run against a real in-browser SQLite engine — the student sees the actual result table, not a “correct ✓”. Truth, instantly.

01

Prompt

A tiny real-world task: “List students who scored above 90.”

02

Attempt

Tap-to-build blocks, fix a bug, or type raw SQL — difficulty scales with skill.

03

Run for real

Query executes on live SQLite. The actual output table appears.

04

Feedback

Right → XP + streak. Wrong → AI tutor explains why, gives a hint, never the answer.

05

Reward & hook

Streak flame, gems, league bump, “come back tomorrow.”

Six challenge formats keep the loop fresh

Build the query

Drag SELECT / FROM / WHERE blocks into the right order. Zero typing — pure concept.

Predict the output

See a query + table, pick the result rows. Trains reading before writing.

Fix the bug

A broken query returns wrong rows. Spot and repair it. Debugging = deep learning.

Free query

Type raw SQL against a live DB, auto-graded on the result set. The real skill.

Data detective

A mystery scenario solved only by querying. Story wrapper = intrinsic motivation.

Ask in English

Type a question, AI shows the SQL. Learn the English→query mapping — the AI skill.

Retention mechanics

Streaks, hearts (lives), gems, XP, weekly leagues, and a daily SQL puzzle (“guess the query from the output”, Wordle-style). Loss aversion + variable reward + social rank.

Boss levels

Each unit ends in a mini-project: “Design the school library database and answer 5 real questions.” Proof they can build, not just answer.

Bit, the AI tutor

Our beaver mascot. Explains mistakes in plain language, adapts difficulty, and generates endless practice at the student's exact level. Hints, never answers.

07 · Access control (RBAC)

Six roles. Least privilege by default.

A minor's account is the most sensitive object in the system, so permissions are deliberately narrow. Parents observe but never act as the child; teachers assign but can't see personal data; content authors touch lessons, never users.

Student

Owns their learning. Plays lessons, sees own progress. No access to anyone else's data. The default account.

Parent / Guardian

Grants consent, views their linked child's progress & time, manages billing. Read-only on learning.

Teacher

Creates classes, assigns units, sees aggregate class progress. No access to PII or parent data.

School Admin

Manages teachers & rosters within their org. Scoped to one school; can't touch content or platform.

Content Author

Builds & edits lessons, puzzles, curriculum. Zero access to any user account or data.

Super Admin

Platform operations, support, safety. Access is logged & audited; break-glass for user data.

08 · MVP scope

What ships in v1 — and what deliberately doesn't.

The bar for v1: a student can sign up, a parent can consent, and the student can form a 3-day streak learning real SQL with an AI tutor. One platform (responsive web PWA), three units, ruthless cuts everywhere else.

✅ In the MVP

  • ›Responsive web PWA — installable, works on any school laptop or phone. Fastest path to real users.
  • ›Units 1–4 (~15 lessons): data basics → SELECT → WHERE → ORDER BY/LIMIT.
  • ›Live SQLite in-browser (sql.js) — real query execution, real result tables.
  • ›4 challenge types: build-the-query, predict-output, fix-the-bug, free-query.
  • ›AI tutor “Bit” — error explanations & hints via LLM API.
  • ›“Ask in English” playground — the NL→SQL wow moment.
  • ›Streaks, XP, hearts, 1 daily puzzle — the minimum viable habit loop.
  • ›Student auth + parent consent + read-only parent dashboard.
  • ›Basic admin to publish lessons & watch funnels.

🔜 Deliberately later

  • ×Native iOS/Android apps (PWA covers v1 feedback).
  • ×Leagues, friends, multiplayer “Query Race.”
  • ×Units 5–10 incl. JOINs, DB design, AI capstone.
  • ×Full teacher classroom tools & assignments.
  • ×Payments / family & school plans.
  • ×AI-generated infinite personalized levels.
  • ×Offline mode, localization.

Each of these earns its way in only after the core loop proves it retains students.

09 · Is it working?

Measure the habit and the learning — not vanity.

Downloads mean nothing. We win only if students keep coming back and can actually query better than last week.

It fuses both truths in one number: they showed up (habit) and they did the work (learning). Everything else is an input to moving this.
